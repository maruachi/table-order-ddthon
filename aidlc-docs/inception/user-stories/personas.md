# 페르소나 (Personas)

테이블오더 서비스의 사용자 원형 정의. 요구사항(`aidlc-docs/inception/requirements/requirements.md`) 기반, 2개 페르소나로 구성한다.

---

## P1. 고객 (Customer) — 테이블 태블릿 이용자

- **역할**: 매장 테이블에 비치된 태블릿으로 직접 메뉴를 보고 주문하는 방문 고객.
- **목표**:
  - 직원 호출 없이 즉시 메뉴를 탐색하고 원하는 항목을 주문한다.
  - 주문 진행 상황(대기중/준비중/완료)을 확인한다.
- **행동/맥락**:
  - 로그인 개념을 인지하지 못함 — 태블릿은 항상 메뉴 화면으로 켜져 있어야 함(자동 로그인).
  - 터치로만 조작하며, 빠르고 직관적인 UX를 기대.
  - 하나의 테이블 세션 동안 여러 번 나눠 주문할 수 있음.
- **니즈**:
  - 카테고리별로 정리된 메뉴, 큰 터치 영역(최소 44x44px), 명확한 총액 표시.
  - 장바구니가 새로고침에도 유지될 것.
  - 현재 자리(세션)에서 낸 주문만 깔끔하게 확인.
- **불만/제약(Pain Points)**:
  - 이전 손님의 주문 내역이 보이면 안 됨(세션 격리).
  - 주문 실패 시 장바구니가 날아가면 안 됨.
- **기술 수준**: 낮음 — 별도 학습 없이 사용 가능해야 함.

## P2. 매장 관리자 (Admin) — 매장 운영/직원

- **역할**: 매장에서 들어오는 주문을 실시간으로 관리하고, 테이블·메뉴·세션을 운영하는 사용자. (본 MVP에서는 직원/매니저 권한 구분 없이 단일 관리자 역할로 통합.)
- **목표**:
  - 신규 주문을 지연 없이 파악하고 조리 상태를 갱신한다.
  - 테이블 태블릿 초기 설정, 이용 완료 처리, 메뉴 관리를 수행한다.
- **행동/맥락**:
  - PC/태블릿에서 관리자 웹에 로그인해 근무 시간 동안 대시보드를 계속 열어 둠(16시간 세션).
  - 여러 테이블을 동시에 모니터링하며 바쁜 시간대에 빠른 대응이 필요.
- **니즈**:
  - 신규 주문이 2초 이내로 화면에 반영(SSE) 및 시각적 강조.
  - 테이블별 그리드 뷰, 카드별 총 주문액과 최신 주문 미리보기.
  - 이용 완료 시 해당 세션 주문을 과거 이력으로 이관하고 현재 상태를 리셋.
  - 매장 데이터가 다른 매장과 격리(멀티테넌시).
- **불만/제약(Pain Points)**:
  - 주문 누락/지연 표시는 치명적.
  - 잘못 들어온 주문을 직권으로 즉시 삭제/수정할 수 있어야 함.
- **기술 수준**: 중간 — 로그인, 대시보드 조작에 익숙.
