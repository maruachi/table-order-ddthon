# 컴포넌트 정의 (Components)

테이블오더 서비스의 고수준 컴포넌트 식별 문서. 상세 비즈니스 규칙은 이후 Construction의 Functional Design(유닛별)에서 정의한다.

**설계 결정 근거** (`application-design-plan.md` 답변):
- Q1-B: 도메인 4분할 + Store·Table 공통 모듈
- Q2-A: Realtime(SSE)은 중앙 인메모리 pub-sub 브로커를 둔 독립 컴포넌트
- Q3-A: 3계층 (Router → Service → Repository)
- Q4-A: SQLAlchemy ORM
- Q5-A: 인증 컨텍스트에서 store_id 주입, 모든 서비스 메서드가 store_id 필수
- Q6-A: 테이블 세션 토큰 기반 고객 인증
- Q7-A: 고객용/관리자용 SPA 2개 분리
- Q8-A: 서비스 간 직접 호출(동기 오케스트레이션)

---

## 아키텍처 개요

```
[고객 SPA (Vue)]        [관리자 SPA (Vue)]
      |                        |
      |  HTTPS/REST + SSE      |
      +-----------+------------+
                  |
          [FastAPI 라우터 계층]
                  |
        (Auth 의존성: store_id/세션 컨텍스트 주입)
                  |
          [서비스 계층 (도메인)]
   Auth · Menu · Order · TableSession · Realtime
                  |
        [리포지토리 계층 (SQLAlchemy)]
                  |
              [SQLite]
```

- **백엔드 컴포넌트 = 도메인 모듈**. 각 모듈은 Router / Service / Repository 3계층으로 내부 구성.
- **Platform/Common**은 모든 도메인이 공유하는 기반(엔티티·DB·인증 의존성).
- **Realtime**은 독립 컴포넌트로, Order/TableSession이 발행한 이벤트를 매장별 인메모리 브로커를 통해 SSE 커넥션에 브로드캐스트.

---

## 백엔드 컴포넌트

### 1. Platform / Common (Store·Table 공통)
- **목적**: 멀티테넌트 기반과 공통 인프라 제공.
- **책임**:
  - `Store`, `Table` 엔티티 정의 및 관리(초기 데이터/시드 포함).
  - DB 세션/엔진 관리(SQLAlchemy), 베이스 리포지토리 패턴.
  - 인증 의존성(현재 요청의 `store_id`·주체 컨텍스트 주입) — 멀티테넌시 강제의 단일 지점(Q5-A).
  - 공통 예외/응답 스키마, 페이지네이션 유틸.
- **인터페이스(제공)**: `get_current_store_context()` 의존성, `BaseRepository`, DB 세션 팩토리, `Store`/`Table` 조회 API.
- **소비**: 없음(최하위 기반 계층).

### 2. Auth (인증)
- **목적**: 관리자·테이블 태블릿 인증 및 토큰 발급/검증.
- **책임**:
  - **관리자 인증(US-A1)**: 매장 식별자 + 사용자명/비밀번호 로그인, bcrypt 검증, JWT(16h) 발급, 로그인 시도 제한.
  - **테이블 인증(US-A4, US-C1)**: 관리자에 의한 테이블 초기 설정(번호/비밀번호), 테이블 세션 토큰 발급, 태블릿 자동 로그인 검증(Q6-A).
  - JWT/테이블 토큰 검증 → Platform의 인증 컨텍스트에 `store_id`(+table_id) 제공.
- **인터페이스(제공)**: 관리자 로그인, 테이블 설정, 테이블 로그인, 토큰 검증 함수.
- **소비**: Platform(Store·Table 조회, DB).

### 3. Menu (메뉴)
- **목적**: 메뉴/카테고리 관리와 고객 메뉴 조회.
- **책임**:
  - 관리자 메뉴 CRUD, 카테고리 분류, 노출 순서 조정, 데이터 검증(필수 필드/가격 범위)(US-A8).
  - 고객 메뉴 조회 — 카테고리별·노출 순서 정렬(US-C2).
  - 매장별 격리(NFR-3).
- **인터페이스(제공)**: 메뉴/카테고리 CRUD, 노출 순서 변경, 고객용 메뉴 목록 조회.
- **소비**: Platform, Auth(권한 컨텍스트).

### 4. Order (주문)
- **목적**: 주문 생성·조회·상태 변경·삭제. (장바구니는 클라이언트 측 — 서버 컴포넌트 없음.)
- **책임**:
  - 주문 생성(US-C4): 메뉴 유효성·금액 계산, 주문 저장, **첫 주문 시 TableSession 시작 오케스트레이션(Q8-A: 직접 호출)**, 이벤트 발행.
  - 현재 세션 주문 조회(US-C5): 현재 세션 격리.
  - 주문 상세 조회 + 상태 변경(대기중/준비중/완료)(US-A3).
  - 주문 삭제(직권)(US-A5): 삭제 후 총액 재계산, 이벤트 발행.
- **인터페이스(제공)**: 주문 생성, 현재 세션 주문 조회, 주문 상세, 상태 변경, 주문 삭제.
- **소비**: Platform, Auth, Menu(단가/유효성), TableSession(세션 시작/현재 세션 조회), Realtime(이벤트 발행).

### 5. TableSession (테이블 세션 · 주문 이력)
- **목적**: 테이블 세션 라이프사이클과 주문 이력 관리 — 서비스 핵심 도메인 로직.
- **책임**:
  - 세션 시작(첫 주문 시)/현재 세션 조회.
  - 세션 종료(이용 완료, US-A6): 해당 세션 주문을 세션 ID·완료 시각과 함께 과거 이력(OrderHistory)으로 이관, 현재 주문/총액 리셋, 이벤트 발행.
  - 과거 주문 내역 조회(US-A7): 테이블별 시간 역순, 날짜 필터.
- **인터페이스(제공)**: 세션 시작, 현재 세션 조회, 세션 종료(이력 이관), 과거 이력 조회.
- **소비**: Platform, Auth, Realtime(이벤트 발행). Order와 상호 참조(주문 이관 시).

### 6. Realtime (실시간 · SSE) — 독립 컴포넌트 (Q2-A)
- **목적**: 매장별 실시간 이벤트 브로드캐스트.
- **책임**:
  - 매장별 인메모리 pub-sub 브로커 관리(store_id → 구독자 집합).
  - SSE 엔드포인트: 관리자 대시보드(US-A2), 고객 주문 상태(US-C6, 선택).
  - Order/TableSession이 발행한 이벤트(신규 주문/상태 변경/삭제/세션 종료)를 해당 매장 구독자에게 2초 이내 전파(NFR-1).
- **인터페이스(제공)**: `publish(store_id, event)`, SSE 스트림 엔드포인트(관리자/고객), 구독/해지.
- **소비**: Platform(store 컨텍스트). Order·TableSession이 이 컴포넌트의 `publish`를 호출.

## 프론트엔드 컴포넌트 (Q7-A: SPA 2개 분리)

### 7. Customer SPA (고객용 Vue 앱)
- **목적**: 태블릿 고객 경험 — 자동 로그인, 메뉴 탐색, 장바구니, 주문, 현재 세션 내역.
- **책임**:
  - 테이블 토큰 로컬 저장·자동 로그인(US-C1).
  - 메뉴 화면(기본 화면)·카테고리 탐색·상세(US-C2).
  - **장바구니 클라이언트 상태**(로컬 저장, 새로고침 유지, 실시간 총액)(US-C3).
  - 주문 확정 플로우(주문번호 표시→5초 후 메뉴 리다이렉트)(US-C4).
  - 현재 세션 주문 내역(US-C5), 선택적 SSE 상태 반영(US-C6).
- **소비**: Auth(테이블 로그인), Menu(조회), Order(생성/조회), Realtime(SSE, 선택).

### 8. Admin SPA (관리자용 Vue 앱)
- **목적**: 실시간 모니터링·테이블/세션·메뉴 관리 콘솔.
- **책임**:
  - 관리자 로그인·JWT 세션 관리(16h)(US-A1).
  - 실시간 대시보드(테이블별 그리드 + SSE)(US-A2), 주문 상세·상태 변경(US-A3).
  - 테이블 초기 설정(US-A4), 주문 삭제(US-A5), 이용 완료/세션 종료(US-A6), 과거 이력(US-A7).
  - 메뉴 관리(CRUD·노출 순서)(US-A8).
- **소비**: Auth(관리자 로그인), Menu(관리), Order(상세/상태/삭제), TableSession(설정/종료/이력), Realtime(SSE).

## 컴포넌트 ↔ 스토리 ↔ 개발자 유닛 매핑

| 컴포넌트 | 관련 스토리 | 예비 개발 유닛(4인 병렬, Units Generation에서 확정) |
|---|---|---|
| Platform/Common | (기반) NFR-3/4 | 공통 기반 — 초기 공동 구축 |
| Auth | US-A1, US-A4, US-C1 | 유닛 1 |
| Menu | US-A8, US-C2 | 유닛 2 |
| Order | US-C4, US-C5, US-A3, US-A5 | 유닛 3 (+ Customer 장바구니) |
| TableSession | US-A6, US-A7 | 유닛 4 |
| Realtime | US-A2, US-C6 (+ US-A3/A5/A6 전파) | 유닛 4 (TableSession과 동일 유닛) |
| Customer SPA | US-C1~C6 | 유닛별 화면 분담 |
| Admin SPA | US-A1~A8 | 유닛별 화면 분담 |

> 참고: Q1-B에 따라 Realtime은 아키텍처상 독립 컴포넌트이나(Q2-A), 4인 병렬 개발 편성에서는 TableSession과 동일 유닛(유닛 4)으로 묶는다. 최종 유닛 경계는 **Units Generation** 단계에서 확정.
