# 테이블오더 서비스 — 요구사항 문서 (Requirements)

## 1. Intent Analysis (의도 분석)

- **User Request**: 테이블오더 서비스 구축. `requirements/table-order-requirements.md`(기능 요구사항)와 `requirements/constraints.md`(제외 범위)를 근거로 AI-DLC 워크플로우로 진행.
- **Request Type**: New Project (Greenfield)
- **Scope Estimate**: System-wide (고객용 웹 UI + 관리자용 웹 UI + 백엔드 API + 데이터 저장소)
- **Complexity Estimate**: Moderate → Complex (실시간 SSE, 세션 라이프사이클, 멀티테넌트, 인증 포함)
- **Requirements Depth**: Standard (기능 요구사항이 상세히 제공됨 + 기술/NFR 결정을 질문으로 확정)

## 3. 기능 요구사항 (Functional Requirements)

출처: `requirements/table-order-requirements.md`. 아래는 구현 대상으로 확정된 요약이며, 원문이 정본이다.

### 3.1 고객용 기능 (Customer)
- **FR-C1 테이블 태블릿 자동 로그인/세션 관리**
  - 관리자가 1회 초기 설정: 매장 식별자, 테이블 번호, 테이블 비밀번호 입력 → 로그인 정보 로컬 저장
  - 1회 로그인 성공 후 저장된 정보로 자동 로그인
- **FR-C2 메뉴 조회 및 탐색**
  - 메뉴 화면이 기본 화면으로 항상 표시
  - 카테고리별 분류/표시, 카테고리 간 빠른 이동
  - 메뉴 상세: 메뉴명, 가격, 설명, 이미지(URL)
  - UI: 카드형 레이아웃, 터치 친화 버튼(최소 44x44px), 명확한 시각적 계층
- **FR-C3 장바구니 관리**
  - 메뉴 추가/삭제, 수량 증감, 총 금액 실시간 계산, 장바구니 비우기
  - 클라이언트 측 임시 저장 (새로고침 시에도 유지), 서버 전송은 주문 확정 시에만
- **FR-C4 주문 생성**
  - 주문 내역 최종 확인 → 주문 확정
  - 성공 플로우: 주문 번호 표시 → 장바구니 자동 비우기 → 메뉴 화면으로 자동 리다이렉트(5초 표시 후)
  - 실패 시: 에러 메시지 표시 및 장바구니 유지
  - 주문 정보: 매장 식별, 테이블 식별, 메뉴 목록(메뉴명/수량/단가), 총 금액, 세션 ID
- **FR-C5 주문 내역 조회 (현재 세션)**
  - 주문 시간 순 정렬, 주문별 상세(주문번호/시각/메뉴·수량/금액/상태: 대기중·준비중·완료)
  - **현재 테이블 세션 주문만** 표시(이전 세션·이용완료 주문 제외)
  - 페이지네이션 또는 무한 스크롤
  - 주문 상태 실시간 업데이트 (선택사항)

### 3.2 관리자용 기능 (Admin)
- **FR-A1 매장 인증**
  - 매장 식별자 + 사용자명/비밀번호 로그인
  - JWT 기반, 16시간 세션 유지, 새로고침 시 유지, 16시간 후 자동 로그아웃
  - 비밀번호 bcrypt 해싱, 로그인 시도 제한
- **FR-A2 실시간 주문 모니터링**
  - Server-Sent Events(SSE) 기반 실시간 업데이트, 2초 이내 주문 표시
  - 그리드/대시보드 레이아웃: 테이블별 카드, 카드별 총 주문액, 최신 주문 n개 미리보기
  - 주문 카드 클릭 시 전체 메뉴 목록 상세, 주문 상태 변경(대기중/준비중/완료)
  - 신규 주문 시각적 강조, 테이블별 필터링
- **FR-A3 테이블 관리**
  - 테이블 태블릿 초기 설정(번호/비밀번호, 16시간 세션 생성, 자동 로그인 활성화)
  - 주문 삭제(직권 수정): 확인 팝업 → 즉시 삭제 → 테이블 총 주문액 재계산 → 성공/실패 피드백
  - 테이블 세션 처리: 세션 시작(첫 주문)/종료(이용 완료) 관리
    - 종료 시 해당 세션 주문을 과거 이력으로 이동, 현재 주문 목록/총 주문액 0으로 리셋
    - 새 고객이 이전 내역 없이 시작 가능
  - 과거 주문 내역 조회: 테이블별 시간 역순, 주문번호/시각/메뉴/총액/이용완료 시각, 날짜 필터
- **FR-A4 메뉴 관리**
  - 카테고리별 조회, 등록(메뉴명/가격/설명/카테고리/이미지 URL), 수정, 삭제, 노출 순서 조정
  - 데이터 검증: 필수 필드, 가격 범위

### 3.3 도메인 개념
- **테이블 세션**: 특정 테이블에서 첫 주문 시작부터 이용 완료 처리까지의 기간. 종료 후 다음 첫 주문 시 새 세션 시작.
- **주문 이력 (OrderHistory)**: 세션 종료 시 주문을 세션 ID로 그룹화하여 완료 시각과 함께 저장.

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **NFR-1 실시간성**: 관리자 모니터링은 SSE로 신규 주문을 2초 이내 표시.
- **NFR-2 인증/세션**: 관리자 JWT 16시간 세션; 테이블 태블릿 자동 로그인 세션. bcrypt 비밀번호 해싱, 로그인 시도 제한. (별도 SECURITY 확장은 미적용 — 아래 5절)
- **NFR-3 멀티테넌시**: 모든 데이터(메뉴/주문/세션/이력)는 매장 식별자로 격리.
- **NFR-4 데이터 영속성**: SQLite에 매장/메뉴/주문/주문이력/세션 저장.
- **NFR-5 클라이언트 영속성**: 장바구니 및 테이블 로그인 정보는 브라우저 로컬 저장(새로고침에도 유지).
- **NFR-6 사용성(고객 UI)**: 터치 친화, 카드형 레이아웃, 최소 44x44px 버튼.
- **NFR-7 규모**: 중규모(여러 매장, 매장당 수십 개 테이블)를 데이터 모델·API 설계에서 고려. 단, 실행 환경은 로컬 개발이며 대규모 성능 최적화는 MVP 범위 외.
- **NFR-8 초기 데이터**: 시드 스크립트 + 관리자 UI 등록 모두 지원.

## 6. 범위 제외 (Out of Scope)

출처: `requirements/constraints.md`. 구현하지 않음:
- 실제 결제/PG 연동/영수증/환불/포인트·쿠폰
- 복잡한 인증(OAuth/SNS), 다단계 인증(2FA/OTP)
- 이미지 리사이징/최적화, CMS, 광고
- 푸시/SMS/이메일/소리·진동 알림
- 주방 전달, 재고 관리
- 데이터 분석/매출 리포트/직원 관리/예약/리뷰/다국어
- 배달 플랫폼·POS·소셜·지도·번역 API 연동

## 7. MVP 개발 범위 (요약)

- **고객용**: 자동 로그인/세션, 메뉴 조회, 장바구니, 주문 생성(5초 표시 후 리다이렉트), 현재 세션 주문 내역
- **관리자용**: 매장 인증(16시간), 실시간 주문 모니터링(그리드+SSE), 테이블 관리(초기 설정/주문 삭제/이용 완료/과거 내역)

## 8. 핵심 요구사항 요약 (Key Requirements Summary)

1. 멀티테넌트 테이블오더 플랫폼 — FastAPI + Vue SPA + SQLite, 로컬 실행.
2. 고객: 무로그인 즉시 주문 경험(자동 로그인, 장바구니 로컬 영속, 주문 생성/조회).
3. 관리자: SSE 기반 실시간 주문 대시보드 + 테이블 세션 라이프사이클 + 메뉴 관리.
4. 테이블 세션 종료 시 주문의 과거 이력 이관 및 현재 상태 리셋이 핵심 도메인 로직.
5. 확장(Security/Resiliency/PBT) 미적용 — 단, 기능 요구사항 내 기본 보안은 구현.
