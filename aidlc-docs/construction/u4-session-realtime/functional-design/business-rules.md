# U4 비즈니스 규칙 (Business Rules)

U4(Session + Realtime) 검증·제약·정책. U0 규칙(BR-U0-*)을 전제로 하며 U4 고유 규칙은 BR-U4-*로 번호를 부여한다.

## 세션 라이프사이클
- **BR-U4-1 (활성 세션 유일성)**: 한 테이블에 `status='active'` 세션은 동시에 최대 1개. DB 부분 유니크 인덱스 + 서비스 트랜잭션 가드로 강제(Q1=C).
- **BR-U4-2 (멱등 시작)**: `start_or_get_active_session`은 활성 세션이 있으면 기존 `session_id`를 반환(중복 생성 금지). 첫 호출에서만 신규 생성.
- **BR-U4-3 (store 격리)**: 모든 세션/이력 조회·변경은 `StoreContext.store_id`로 스코프. 클라이언트가 보낸 store_id/session_id는 신뢰하지 않으며 항상 컨텍스트 매장 내에서만 유효(BR-U0-3, NFR-3). `BaseRepository`로 강제.
- **BR-U4-4 (종료 원자성)**: 세션 종료의 이력 스냅샷 저장·상태 전이·주문 아카이브 마킹(계약 C)은 단일 트랜잭션. 중간 실패 시 전체 롤백(세션은 여전히 active).
- **BR-U4-5 (종료 대상 검증)**: 활성 세션이 없는 테이블에 종료 요청 시 종료 대상 없음(no active session) 오류/안내. 주문 0건인 활성 세션은 정상 종료하며 이력에 주문 0건으로 기록(Q9=A).
- **BR-U4-6 (총액 소유권)**: `TableSession.total_amount`의 진행 중 갱신은 U3(주문 생성/삭제 시 재계산)가 책임진다(U3 정의와 일치). U4는 종료 시점에 수집 주문 합으로 총액을 확정하고 이후 리셋 상태를 보장한다.

## 이력 (US-A7)
- **BR-U4-7 (이력 자립성)**: 과거 이력은 종료 시점 스냅샷(`SessionHistoryOrder`/`Line`)으로 저장되어, 이후 메뉴·주문 변경이나 U3 가용성과 무관하게 조회 가능하다(런타임 U3 의존 없음).
- **BR-U4-8 (정렬·필터)**: 이력은 `closed_at` 역순 기본 정렬. 날짜 필터 기준 필드는 `closed_at`(Q6=A). table_id 필터 지원. 페이지네이션 적용(U0 `Page`).

## 실시간 (pub-sub / SSE)
- **BR-U4-9 (best-effort 발행)**: 이벤트 발행 실패는 주 트랜잭션(주문/세션 쓰기)을 절대 깨지 않는다(BR-U0-13). U0 `publish` 헬퍼의 예외 격리를 유지.
- **BR-U4-10 (구독 격리)**: 구독자는 자신의 `store_id` 이벤트만 수신. 관리자 스트림=매장 전체, 고객 스트림=`table_id` 필터 적용(Q8=A). 타 매장/타 테이블 이벤트 유출 금지(NFR-3).
- **BR-U4-11 (SSE 인증)**: SSE 연결은 query param 토큰을 검증해 `StoreContext`를 해석한 뒤에만 구독 허용(EventSource가 헤더를 못 보내므로). 유효하지 않으면 연결 거부.
- **BR-U4-12 (전파 지연)**: 발행~구독자 수신 지연 2초 이내(NFR-1). 인메모리 fan-out으로 달성.
- **BR-U4-13 (라이브 상태 휘발)**: 브로커는 인메모리 — 서버 재시작 시 진행 중 SSE 상태는 유실 허용. 세션/이력은 SQLite 영속(NFR-4). 재연결 시 REST 스냅샷 재조회로 재동기화(Q7=C).
- **BR-U4-14 (keepalive)**: SSE 스트림은 주기적 keepalive(주석 프레임)로 유휴 연결을 유지하고, 연결 종료 시 구독자를 즉시 정리(리소스 누수 방지).

## 검증/입력
- **BR-U4-15**: 이력 조회 페이지 파라미터는 U0 `PageParams`(offset≥0, 1≤limit≤200) 규약을 따른다.
- **BR-U4-16**: 대시보드 미리보기 개수 n은 기본 3(Q5=A). 음수/과대 값은 기본값으로 보정.
